# 评估闭环手册

原则:任何未经评估的优化都只是猜测。评估不通过则回滚。

## Golden Set 构建

1. 收集 10-20 个真实任务样本:每个样本 = 一份真实输入 + 该输入下的期望产出
   (样本形态由 skill 领域决定,如一份材料/一段需求/一个数据文件)
2. 每个样本预先标注已知要点/期望锚点(命名按领域:问题/要点/结论锚点):
   - 2-3 个高价值要点(P0 级)
   - 若干中价值要点(P1 级)
   - 若干规范/格式类要点(P2 级)
3. 样本须覆盖:典型场景、边界场景、至少一个大体量输入
   (用于暴露 context rot)

## 四指标 A/B

对同一 golden set 分别运行优化前后两版 skill,统计:

| 指标 | 定义 | 方向 | 权重 |
|---|---|---|---|
| 核心目标召回/达成率 | 命中的预埋高价值要点数 / 预埋总数 | 越高越好 | 最高 |
| 无效输出率 | 不成立的输出条目 / 总条目 | 越低越好 | 高 |
| 低价值条目占比 | 低优先级条目 / 总条目 | 越低越好 | 中 |
| 输出长度 | 总字数或总条目数 | 信息密度代理 | 参考 |

指标命名按 skill 领域自适应填充(如召回率/覆盖率/准确率、
跑题率/臆造率/格式偏差率),框架与判定规则不变。

判定规则(以"召回/达成率"简称核心指标):
- 核心指标提升且无效输出率未恶化 → 优化成立
- 核心指标提升但无效输出率显著上升 → 条目改写过度,放宽触发条件
- 核心指标下降 → 回滚,重新诊断(大概率删错了增量知识)
- 核心指标持平但输出更短更密 → 成立(低价值条目被压缩)

## 逐项消融(可选,用于精细定位)

当整体 A/B 无法定位收益来源时,分五次单独验证:
1. 只删通用知识,其余不动 → 验证知识提纯的独立贡献
2. 只加路由表,其余不动 → 验证分层加载的独立贡献
3. 只改条目格式 → 验证可执行化改造的贡献
4. 只改两阶段流程 → 验证工作流的贡献
5. 组合全部 → 验证无负向叠加

## 注意事项

- 不同模型上结论可能不同;skill 换用模型后须重跑评估
  (条件允许时跨模型档位各跑一轮,避免对单一档位过拟合)
- golden set 会随时间失效,每季度补充新样本
- 保留每次 A/B 的原始输出,便于事后比对
- 报告 delta 视角:优化版多花/省下的 token 与时间,买到了什么——
  成本上升而核心指标无提升的改动不采纳
- 触发质量与输出质量分开测:should-trigger / should-not-trigger
  两组提示词实测触发命中率,不计入四指标
- 有条件时用 LLM-as-judge 按预埋锚点自动判分,但 PASS 必须给出
  原文证据,人工抽检校准判分标准
